## Retrieval validation

- The lexical and passage layers are batch-scoped and preserve source file,
  section, evidence text, and physical PDF page metadata.
- SQLite FTS5 is the default retrieval path.
- A controlled synthetic benchmark used 80 passages and 60 queries across
  Exact, Paraphrase, Biomedical, and Hard Negative categories.
- FTS5 remained strong on exact queries; semantic retrieval improved some
  semantic recall cases; Hybrid RRF combines the candidate sets.
- PubMedBERT is the current recommended local profile for this controlled
  benchmark only. It is not a claim that PubMedBERT is the best model for all
  scientific papers or biomedical production workloads.
- Detailed benchmark data is in
  [`v0.4_embedding_benchmark.md`](v0.4_embedding_benchmark.md).

## Privacy and model lifecycle

- Local Offline PDF extraction and Lexical / FTS5 retrieval are local.
- Hybrid Local uses a user-provided local SentenceTransformer directory and
  requires optional semantic dependencies.
- The application does not automatically download embedding models or load a
  semantic model during ordinary startup or PDF upload.
- Evidence Only makes no Provider request.
- Experimental Provider Grounded QA sends only selected EvidencePack snippets
  when the user explicitly chooses a Provider; it does not send the whole PDF
  by default.

## Grounded QA validation boundary

The grounded core validates JSON shape, known Evidence IDs, and deterministic
program-bound source/section/physical-page rendering. `verified=true` retains
its existing meaning: the original extracted text matches the corresponding
PDF page. It does not establish scientific truth or semantic entailment.

The following facts are recorded accurately:

- Mock/Fake grounded QA validation: PASS;
- DeepSeek transport: real success in a controlled synthetic request;
- DeepSeek supported synthetic response after safe syntax-level normalization:
  parse, schema, citation, and status checks passed;
- local abstention: PASS;
- combined adversarial prompt-injection live scenario: NOT COMPLETED;
- full real-provider grounded QA validation: INCOMPLETE.

The compatibility layer only maps an exact string `claim` field to `text`
when `text` is absent, and a non-empty string `limitations` value to a
one-item list. It does not repair citations, pages, sources, sections, status
casing, or unknown fields.

## Known limitations

- Text-based PDFs only; no OCR.
- Complex tables, formulas, and image-based content may extract poorly.
- The semantic benchmark is primarily synthetic.
- There is no production-scale vector index; semantic passage scope is capped.
- Optional semantic dependencies are heavier than the base installation.
- Citation validation is not semantic entailment and does not guarantee no
  hallucinations.
- Scientific truth validation, peer-review validation, replication, and
  clinical validity are out of scope.
- Provider Grounded QA remains Experimental.
