# v0.4 检索架构开发说明

## Phase 9C1 状态

- `LexicalRetriever` 已适配本地 SQLite passage 检索。
- `SemanticRetriever` 只定义接口，默认使用 `NullSemanticRetriever`。
- `HybridRetriever` 和 Reciprocal Rank Fusion（RRF）已实现，可通过 mock 进行确定性测试。
- 未安装或下载 embedding 模型。
- 未调用 embedding API，也没有真实 semantic backend。
- 生产界面默认仍为 `Lexical Retrieval Only`。

`retrieval_sources` 表示 passage 被哪些检索器找到，不表示证据已经验证，也不表示科研结论正确。`verified` 仍属于原有 evidence 语义，不能由检索器设置。

## 安全边界

Hybrid 融合前会根据当前批次允许的 `passage_id` 丢弃未知结果，避免 semantic backend 引入其他批次的文本。semantic backend 出错时返回 lexical 结果，并通过状态和 warning 明确标记，不静默伪装成完整 hybrid 检索。

## Phase 9C2 计划

后续阶段可接入明确、可选的本地 semantic backend。接入前需要单独验证模型依赖、资源占用、索引生命周期、批次隔离和隐私边界；本阶段不把 mock 验收描述为真实语义搜索能力。
