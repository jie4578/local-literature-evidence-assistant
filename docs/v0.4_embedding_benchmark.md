# v0.4 Local Embedding Benchmark

## Scope and disclosure

This is a **SYNTHETIC / CONTROLLED BENCHMARK**. It contains 80 program-authored scientific passages and 60 manually judged queries. It is not real biomedical corpus validation and does not use `paper/`, `manual_validation/`, user PDFs, or remote inference.

The benchmark ran offline on CPU after the three explicitly authorized Hugging Face model downloads. It compares one lexical baseline with semantic-only and lexical-plus-semantic RRF retrieval.

For every model, the first build encoded 80 passages and the second build reused 80 cached vectors with zero re-encodes. The three fingerprints were distinct. A separate temporary batch check returned only its own passage, confirming batch isolation.

## Selection

`DEFAULT_RECOMMENDED_LOCAL_MODEL = pubmedbert-base-embeddings`

This is a recommendation for this controlled benchmark only. PubMedBERT hybrid had the highest hybrid MRR@10 (0.8947), tied the best hybrid Recall@5 (0.9667), and had the strongest biomedical subset MRR@10 (0.9333). It is slower and larger than BGE/E5, so the recommendation is quality-first rather than cost-first. FTS5 remained strongest on exact lexical queries, which is expected; hybrid retrieval is intended to preserve that strength while improving broader matching, not to win every category.

This result does **not** establish that PubMedBERT is best for all scientific papers or production workloads. No real biomedical corpus was used.

## Reproducibility and limitations

- The benchmark corpus and relevance labels are committed synthetic fixtures.
- The runtime uses local model directories, CPU, `local_files_only=True`, and `trust_remote_code=False`.
- The benchmark result contains summary metrics, dimensions, prefixes, fingerprints, timings, and cache counts only; it contains no model path, model weights, SQLite cache, or raw corpus export.
- The reported load times are observed in one CPU process; the first loaded model also includes one-time library import cost.
- More validation is required before enabling semantic retrieval in the user-facing UI or selecting a default for real literature.
