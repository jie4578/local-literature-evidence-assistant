# Grounded Evidence Q&A Core

## Implemented

- `EvidencePack` is built only from the existing current-batch retrieval response.
- The program assigns deterministic `E1`, `E2`, … IDs after retrieval.
- Evidence is capped at 8 passages, 1,200 characters per passage, and 8,000
  provider-input characters by default. Original passage text and metadata remain
  available to the local renderer; only the provider payload is bounded.
- `GroundedAnswer` accepts only structured claims linked to known evidence IDs.
- Unknown or missing citations are removed; no provider-supplied filename,
  section, or page is trusted.
- The renderer fills source file, section, and physical PDF page from the
  `EvidencePack`, including multi-page ranges.
- Empty retrieval deterministically abstains without creating or calling a
  Provider.
- The UI exposes `Evidence Only` by default. It shows retrieved source text and
  does not generate a natural-language conclusion.
- Provider-grounded answering is implemented as a dependency-injected,
  mock-testable core, but it is not enabled in the UI in this phase.

## Safety boundary

Evidence is sent to an optional Provider only as explicitly selected, bounded,
quoted data. It is marked as untrusted source material, and prompt-like text
inside it must not be followed. Questions are not persisted to SQLite,
manifests, status files, logs, or output artifacts.

`citation validated` means only that an evidence ID exists in the current
EvidencePack and that its source/page metadata was programmatically bound. It
does not mean that a scientific claim is true, peer-reviewed, replicated,
clinically valid, or semantically entailed.

## Not yet validated

- Real Provider grounded Q&A.
- Semantic entailment correctness.
- Scientific truth or clinical validity.
- Validation on a real biomedical corpus.

- The prompt-injection scenario did not follow the injected instruction, but
  the received structured output did not pass the grounded-answer validation
  path.

  unselected/full-document sentinels were excluded before a Provider call.
- The synthetic-only harness requires explicit live authorization, enforces a
  maximum of three generation attempts, uses no retries or JSON repair, and
  never persists raw Provider payloads or responses.
