# v0.4 Local Hybrid Retrieval UI

## Scope

Local Offline remains the default and uses SQLite FTS5. `Hybrid Local` is an
explicit, opt-in retrieval mode for the current batch. Selecting the mode only
reveals configuration; it does not load a model, download files, or build an
index.

## Lifecycle and privacy

The user must click **构建 / 加载当前批次语义索引** after a valid Local Offline
batch exists. The model directory must already exist locally. The application
does not install dependencies, download models, or contact a remote endpoint.
The semantic UI state contains only serializable status, profile, fingerprint,
batch identity, dimension, and counters. It does not contain model paths,
paper text, credentials, or model objects.

Models are held only in a process-local read-only LRU cache with a maximum of
two entries. A new batch invalidates the previous ready state and its passage
scope. A profile or model-directory change also requires an explicit rebuild.
If the semantic backend is unavailable, search returns the current batch's
lexical results with a clear Chinese fallback warning.

## Profiles

The UI provides PubMedBERT, BGE Small EN v1.5, E5 Small v2, and Custom Local
SentenceTransformer profiles. E5 uses the required `query:` and `passage:`
prefixes. Profiles are configuration labels; the user supplies a local model
directory and is responsible for obtaining the model files separately.

## Evidence boundary

Hybrid retrieval changes ranking only. Source file, section, physical PDF page
range, and evidence text continue to come from the current local index. The
retrieval layer does not generate or rewrite evidence and does not change the
existing `verified` evidence rule.

## Validation status

The deterministic retrieval tests and UI lifecycle tests run offline. The
optional real-model UI acceptance uses a generated synthetic PDF and an
already-present local model in offline mode. It is not validation on a real
biomedical corpus; no claim of biomedical-corpus validation is made here.
